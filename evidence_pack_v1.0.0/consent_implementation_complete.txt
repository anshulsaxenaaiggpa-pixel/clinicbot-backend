## 1. Model Created ✅

**File**: `app/models/consent.py`
- PostgreSQL-ready with UUID and Boolean types
- Tracks: phone, clinic_id, consent_given, version, timestamp
- Immutable audit trail (timestamp cannot be changed)
- Index on clinic_id + phone for fast lookups

```python
class ConsentLog(Base):
    __tablename__ = "consent_log"
    
    id = Column(UUID, primary_key=True, default=uuid.uuid4)
    phone = Column(String(15), nullable=False, index=True)
    clinic_id = Column(UUID, ForeignKey("clinics.id"), nullable=False)
    consent_given = Column(Boolean, nullable=False)
   consent_source = Column(String(20), default="whatsapp", nullable=False)
    consent_version = Column(String(20), default="v1.0", nullable=False)
    consent_text = Column(String, nullable=False)  # Full text shown
    timestamp = Column(DateTime(timezone=True), default=datetime.utcnow, nullable=False)
    ip_address = Column(String(50), nullable=True)
```

## 3. WhatsApp Integration ✅

**File**: `app/services/whatsapp_handler.py`

### Consent-First Flow:
1. User messages clinic's WhatsApp
2. **CONSENT CHECK** runs before any other action
3. If no consent → Show consent prompt
4. User replies "1" → Grant consent + allow booking
5. User replies "2" → Deny consent + block booking
6. Any other message → Re-show consent prompt

### Code Location:
- Lines 112-149 in `whatsapp_handler.py`
- Consent import: Line 12
- Consent logic: Before patient creation

## 6. Compliance Checklist

✅ **DPDP Act 2023**:
- Explicit consent before processing
- Data minimization (phone + name only)
- Purpose limitation (appointments only)
- Right to withdraw (decline option)

✅ **GDPR Article 7**:
- Clear consent request
- Freely given (option to decline)
- Specific purpose stated
- Withdrawable (can decline anytime)

✅ **Evidence Requirements**:
- Timestamp of consent
- Full consent text stored
- User response recorded
- Version tracking (v1.0)
